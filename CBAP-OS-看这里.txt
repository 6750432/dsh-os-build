CBAP OS · 专门给 CBAP 用的可版本化系统
════════════════════════════════════════════════════════════

【它是什么】

Debian 13 (trixie) + XFCE 底座，加上 CBAP 运行时层：

    Python 3
    CBAP 多版本槽
    开机选择 CBAP / Python 版本
    登录后热切换

不是把某个 CBAP 版本焊死在镜像里。

【启动】

    bash 启动CBAP-OS.sh

第一次会弹一次密码框拿 KVM。以后不弹：

    sudo usermod -aG kvm <用户>

【开机选版本】

ISO 的版本选择在 GRUB 菜单里：每个已安装 CBAP 槽一项，例如：

    CBAP OS 0.1 - CBAP v1.4.0 / Python 3.13
    CBAP OS 0.1 - CBAP v1.0.0 / Python 3.13

安装到磁盘的系统还带有 tty1 菜单；ISO 用 GRUB，所以启动参数带 cbap.nomenu。
tty1 菜单内容示例：

    CBAP version:
      [1] v1.4.0
      [2] v1.0.0
    Python runtime:
      [1] 3.13

10 秒不选用默认。无头/串口机器用内核参数：

    cbap.cbap=v1.4.0 cbap.python=3.13

不想看菜单：

    cbap.nomenu

【进系统后热切换】

    sudo cbap-os list
    sudo cbap-os status
    sudo cbap-os use --cbap v1.0.0 --python 3.13
    sudo cbap-os rollback

注意：Python 切换会重启 CBAP 进程；不是在一个已加载 libpython 的
进程里原地换解释器。正在跑的 lease 不会跨切换迁移。

【CBAP 命令】

    cbap --help
    cbap-python --version

`cbap` 使用当前选中的 CBAP 源码和 Python；`cbap-python` 使用当前选中
的 Python。系统自带的 /usr/bin/python3 不被覆盖，apt 仍然正常。

【服务】

    systemctl status cbap
    systemctl restart cbap
    journalctl -u cbap -f

只有存在 hand socket 时 cbap.service 才会真正启动：

    /run/cyberdyne/cyberdyne.sock

没有 hand 时服务被跳过，不会把系统拖进 failed。

【ISO】

带 GRUB 的 live ISO 构建：

    bash cbap-os/iso/build-iso.sh \
      --rootfs ~/拼装/构建/kernel-rootfs \
      --cbap-src ~/cyberdyne-bridge \
      --output ~/拼装/构建/CBAP-OS.iso

需要 mtools、grub-pc-bin、grub-efi-amd64-bin、xorriso、squashfs-tools、
cpio。启动后是 squashfs 只读 lower + tmpfs upper overlay。

【登录信息】

    普通用户    dsh / dsh
    管理员      root / root
    主机名      cbapos

【重要边界】

    没有预编译镜像；本仓库只放构建脚本和文档
    本次没有在真实 QEMU 里验证 CBAP 版本菜单
    没有 TPM/签名/远程证明
    默认 Python 槽链接系统解释器，不是独立 Python 二进制
    切换 CBAP/Python 会中断当前 CBAP 进程

构建顺序见 README.md。
