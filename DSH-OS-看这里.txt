    （pkexec 不认相对路径，一定写全路径）


【想自己改点东西】

    · 想加/减软件：改 加包.sh 里的组（X XFCE PANEL THEME TWEAK CJK AV DEV OURS VIRT），
      然后   pkexec bash ~/拼装/加包.sh <组名>
      它是**增量**的，跑不完可以再跑一次接着做（会先给中断的 dpkg 收尾）。

    · 改完要重新生成镜像才能开机看到：跑  本轮A-开机看桌面.sh

    · 想改主题/壁纸/面板：正常在 DSH OS 桌面里改就行；
      但重启后会回到默认 —— 因为改动在 rootfs 里没落盘到镜像，
      得重跑 本轮A 生成新镜像。（或提出需求，可加一个"保存状态"的开关）


【改名这件事踩过的坑】（留个记录，别再踩）

    XFCE 的壁纸存在 xfconf 渠道 xfce4-desktop 里，
    文件名必须叫  xfce4-desktop.xml  —— 一开始写成了 xfdesktop.xml，
    结果根本没人读它，xfdesktop 就回落到它编译进去的默认图
    （/usr/share/backgrounds/xfce/xfce-x.svg，Debian 那只老鼠），
    所以第一轮开机壁纸还是 Debian 的。

    现在三重保险：① 写对文件名（系统级 /etc/xdg + 用户预置各一份）
    ② 主题里 wallpaper 那几张（含 svg）全换成 DSH OS
    ③ 连那张默认兜底图 xfce-x.svg 也换掉了。
    实测 2026-09-26 01:47 开机：壁纸 = DSH OS，面板用户名 = dsh。✔


【没做 / 没验的（说实话）】

    · 「搬入其它项目」这条不在范围内，所以没做
    · 界面语言还是英文（DejaVu/Noto CJK 都在，中文能显示能输入，
      只是 UI 文案是英文）。想要中文界面：把 LANG=zh_CN.UTF-8 写进
      /etc/environment 就行 —— 一行的事，需要改动说一声
    · 没测过真机安装（现在只在 QEMU 里跑）
    · Windows 直通只把「能力」备好了，**没真跑过一次**
      （要真跑得先回 Windows 关掉「快速启动」，再把你的 Windows 分区
         —— 用 `lsblk` 自己确认是哪一块，例如 /dev/sdXy —— 加进 virt-manager）
    · VM 里没有真显卡（vulkan 是 llvmpipe 软件渲染），所以插帧工具那种
      吃 GPU 的活在里面会慢 —— 真机上不会有这个问题


【关于那次 OOM】（2026-09-25 23:15）

    构建过程把宿主机搞崩了，不做辩解。原因三条：
      ① 没给构建套任何内存上限
      ② 把宿主的 /dev 和 /run rbind 进了 chroot（最危险的设计错误）
      ③ 它被超时掐掉后其实没死（实测后台任务会活下来），轮询又加重了负载

    现在所有构建脚本都带三条护栏：
      · systemd-run --scope -p MemoryMax=4G -p MemorySwapMax=2G
        -p CPUQuota=250% -p IOWeight=40   ← 出事只杀构建，碰不到桌面
      · chroot 里造**私有**最小 /dev + 私有限大小 /dev/shm、/run
      · 开跑前查 MemAvailable，不够直接拒跑

    后半程全程宿主可用内存稳定在 10G 上下。
